## 📜 چه چیزهایی در v1.7.0 تغییر کرد؟ (قیفِ تست از پایه درست شد)

مشکلِ نسخه‌ی قبل: برنامه می‌گفت «هیچ سروری کار نمی‌کند» در حالی که اکثر سرورها سالم بودند — خودِ **قیفِ تست** همه‌چیز را رد می‌کرد. v1.7 هر ردِ کاذب را می‌بندد:

- 🌐 **«باز شدن سایت» = هر پاسخ HTTP — حتی ۴۰۳/۴۲۹**: اینستاگرام به IPهای دیتاسنتر خیلی وقت‌ها ۴۰۳/۴۲۹ می‌دهد ولی همین پاسخ هم یعنی تونل TLS تا مقصد می‌رسد. قبلاً شرطِ `status<400` کانفیگ‌های سالم را همین‌جا رد می‌کرد (از این مرحله به بعد هیچ‌وقت نمی‌رسیدند به تست سرعت!)
- 🏎 **سرعت از ۴ اندپوینتِ مستقل سنجیده می‌شود**: کلادفلر + گوگل + هتزنر + OVH. کانفیگ‌هایی که از پشتِ کلادفلر خارج می‌شوند (اکثر کانفیگ‌های ws رایگان!) از `speed.cloudflare.com` ۴۰۳/۴۲۹ می‌گیرند — قبلاً این یعنی «سرعت صفر» و رد؛ حالا اندپوینتِ بعدی امتحان می‌شود و بهترین اندازه ملاک است. **دروازه‌ی اتصال و نگهبانِ وسط کار هم همین‌طور**
- 🧵 **همزمانیِ تست پینگ ۴۸ → ۱۴**: ۴۸ Xrayِ همزمان روی لینک ایرانی خودش تایم‌اوت می‌سازد و همه را رد می‌کرد. + ردهایِ پینگ **یک بار دیگر** امتحان می‌شوند (تایم‌اوتِ لحظه‌ی شلوغی = ردِ کاذب)
- 🆘 **«هیچ‌کدام کار نمی‌کند» دیگر بن‌بست نیست**: اگر هیچ کاندیدی سرعتِ تأییدشده نداشت، برنامه به **کم‌پینگ‌ترینِ سالم‌ها** وصل می‌شود (حالت اضطراری، دروازه‌ی شُل‌تر) — اگر عملاً بی‌سرعت بود، نگهبان خودش سرور را عوض می‌کند
- 📊 **گزارشِ قیفِ تست با دلیلِ رد**: آخرِ هر اسکن می‌بینید دقیقاً کجا رد شدند: `دریافت ۳۲۰۰ ← زنده ۴۱۰ ← پینگ ۳۷ ← سایت ۵ ← سرعتِ تأیید ۲ (دلایلِ رد: http_403=۲۱، تایم‌اوت=۱۱…)` — دیگر تشخیصِ مشکلات حدسی نیست
- 🔬 **تستِ سلامتِ ابزارِ تست**: قبل از هر اسکن، اندپوینت‌های سرعت مستقیم (بدون تونل) چک می‌شوند — اگر مشکل از خودِ شبکه‌تان باشد، دیگر اشتباهی به گردنِ سرورها نمی‌افتد
- 📄 **فایلِ کانفیگِ شخصی**: `%APPDATA%\ManjarVPN\my_configs.txt` بسازید و هر خط یک کانفیگ (`vless://…`) یا لینک اشتراک بگذارید (سرور شخصی = پایدارترین مسیر) — این‌ها همیشه اول تست می‌شوند و هرگز حذفِ نمونه‌گیری نمی‌شوند
- 🤖 **نجات با هوش مصنوعی حالا سوییچ دارد (پیش‌فرض خاموش)**: مدلِ زبانی کانفیگِ زنده نمی‌شناسد و اکثراً UUID ساختگی می‌دهد؛ اگر خواستید امتحان کنید سوییچِ «🤖 نجات با AI» را روشن کنید (سهمیه ۲ در هر نشست؛ endpoint شخصی همچنان با `ai_settings.json`)
- ➕ دو منبع فعالِ تازه (۳۹ منبع؛ هر ۳۷ منبع قبلی هم تست شد و زنده‌اند)

## 📜 چه چیزهایی در v1.5.0 تغییر کرد؟ (داستانِ «وصل می‌شود ولی کار نمی‌کند»)

- 🚫 **دیگر هیچ‌وقت به سرورِ «فقط‌پینگی» وصل نمی‌شود**: سرعتِ واقعی دیگر تزئینی نیست، شرطِ اتصال است. حداقل سرعتِ قبلی (۰٫۳ Mbps) به **۲٫۰ Mbps** رسید و کفِ مطلقِ قابل‌استفاده (۰٫۶ Mbps) تعریف شد — زیرِ کف، کاندید در هر مرحله‌ای رد می‌شود و برنامه سراغ سرور بعدی می‌رود
- 🏎 **تستِ سرعتِ «پایدار» مثل مرورگر واقعی**: قبلاً یک دانلود تکی بود که بعد از ۳۰۰KB قطع می‌شد → «سرعتِ شروع» را نشان می‌داد نه سرعتِ واقعی. حالا **۳ دانلودِ موازی از CDNهای متفاوت** (کلادفلر ×۲ + ویدیوی نمونه از CDN گوگل) به مدت ۶ ثانیه اجرا می‌شود و سرعت فقط از ثانیه‌ی ۱٫۵ به بعد حساب می‌شود تا اثر slow-start حذف شود — سرورهایی که بعد از چند کیلوبایت برش می‌زنند اینجا لو می‌روند
- 🚪 **دروازه‌ی سرعت قبل از اتصال**: حتی بعد از وصل‌شدنِ تونل، قبل از روشن‌شدنِ پروکسی سیستم یک نمونه‌ی سرعت واقعی گرفته می‌شود؛ اگر زیر ۱ Mbps باشد اتصال رد می‌شود و به‌صورت خودکار کاندیدِ بعدی تست می‌شود
- 🩺 **نگهبانِ حساس به سرعت**: قبلاً نگهبان فقط «پینگ» را می‌گفت و تونلِ «فقط‌پینگی» سالم حساب می‌شد. حالا هر ~۸ ثانیه سرعت تونل هم سنجیده می‌شود؛ اگر پینگ سالم باشد ولی سرعت ۳ نمونه‌ی متوالی عملاً صفر باشد → **تعویض بی‌صدای سرور** بدون دخالت کاربر
- 🔒 نسخه‌ی Xray-core در بیلد **پین شد** (دیگر «latest» نیست) تا رفتار برنامه با آپدیت‌های هسته عوض نشود
- 🧪 تستِ عمیقِ همزمان از ۵ به ۳ کاهش یافت تا پهنای‌باندِ خودِ کاربر اشباع نشود و اعداد تمیزتر باشند

## 🚀 ساخت exe با GitHub Actions — روش بدون گیت (ساده)

1. وارد [github.com](https://github.com) شوید و ثبت‌نام/ورود کنید.
2. دکمه `+` بالا سمت راست → **New repository** → اسم دلخواه (مثلاً `manjarvpn`) → Public → **Create repository**.
3. در صفحه جدید روی **«uploading an existing file»** کلیک کنید.
4. **تمام محتویات پوشه `manjarvpn`** (شامل پوشه `.github`، فایل‌های `main.py`، `engine.py`، `requirements.txt` و …) را بکشید و رها کنید → **Commit changes**.
5. به تب **Actions** بروید؛ بیلد خودکار شروع می‌شود (حدود ۳ تا ۵ دقیقه).
6. روی آخرین اجرا (سبز رنگ ✓) کلیک کنید → پایین صفحه بخش **Artifacts** → دانلود `ManjarVPN-windows-exe` → فایل zip را باز کنید → `ManjarVPN.exe`.

## 📱 استفاده

1. `ManjarVPN.exe` را اجرا کنید (اگر SmartScreen هشدار داد: More info → Run anyway؛ هشدار آنتی‌ویروس برای فایل‌های PyInstaller رایج است و False Positive محسوب می‌شود).
2. دکمه سبز **«اتصال خودکار»** را بزنید.
3. برنامه به ترتیب:
   - ✅ اینترنت مستقیم شما را چک می‌کند + سلامتِ ابزارِ تست را می‌سنجد
   - 📄 اگر `my_configs.txt` داشته باشید، کانفیگ‌های شخصی اول تست می‌شوند
   - 📥 کانفیگ‌ها را از **۳۹ منبع زنده** دریافت می‌کند (آپدیت روزانه)
   - 🏓 صدها کانفیگ را **به‌صورت موازی** از نظر پینگ تست می‌کند (ردها یک بار دیگر امتحان می‌شوند)
   - 🎯 کم‌پینگ‌ترین‌ها را **تست عمیق** می‌کند: با همان کانفیگ **یوتوب، اینستاگرام و تلگرام را واقعا باز می‌کند** (هر پاسخ HTTP = باز شده) + **سرعت واقعی دانلود و آپلود** می‌سنجد (از ۴ اندپوینتِ مستقل)
   - 🆘 اگر هیچ کاندیدی سرعتِ تأییدشده نداشت، به کم‌پینگ‌ترینِ سالم‌ها وصل می‌شود و نگهبان بقیه‌اش را می‌گیرد
   - 🔌 به سروری وصل می‌شود که **هم پینگ و هم سرعت بهتر است و سایت‌ها را واقعا باز کرده**؛ بعد **پروکسی سیستم ویندوز** را روی `127.0.0.1:10809` (HTTP) و `127.0.0.1:10808` (SOCKS) تنظیم می‌کند
4. برای قطع، همان دکمه (قرمز) را بزنید؛ پروکسی سیستم هم خاموش می‌شود. بستن برنامه (✕) هم همه‌چیز را تمیز می‌کند — حتی وسط تست.
5. گزارشِ «نمایش گزارش اتصال» آخرِ هر اسکن **قیفِ تست** را نشان می‌دهد: دقیقاً چند کانفیگ در هر مرحله رد شده و چرا.

## 🔧 تنظیمات (در فایل `engine.py`)

| ثابت | پیش‌فرض | توضیح |
| --- | --- | --- |
| `MAX_TEST_NODES` | `1200` | حداکثر تعداد کانفیگی که پینگ‌تست می‌شود (بیشتر = کامل‌تر ولی کندتر) |
| `MAX_XRAY_LATENCY_TESTS` | `320` | سقف تست پینگ واقعی بعد از پیش‌فیلتر |
| `CONCURRENT_TESTS` | `14` | تست‌های همزمان پینگ (v1.7: از ۴۸ کم شد — همزمانیِ بالا روی لینک ایران تایم‌اوتِ کاذب می‌سازد) |
| `SPEED_ENDPOINTS` | کلادفلر، گوگل، هتزنر، OVH | اندپوینت‌های سرعت — آبشاری: اگر یکی جواب نداد بعدی |
| `DEEP_POOL` / `DEEP_TARGET` | `40` / `12` | چند کاندیدِ کم‌پینگ تست عمیق (سایت‌ها + دان/آپ) شوند / حداقل چند نتیجه کامل |
| `SITE_TARGETS` | یوتوب، اینستاگرام، تلگرام | سایت‌هایی که با هر کاندید واقعا باز می‌شوند (هر پاسخ HTTP = باز شده) |
| `TOP_SPEED_TESTS` | `8` | در حالت fallback، چند کانفیگِ برتر پینگ تست سرعت ساده شوند |
| `SUBSCRIPTION_SOURCES` | ۳۹ منبع | لیست منابع؛ یا فایلِ `my_configs.txt` را پر کنید |

زمان کل تست معمولاً **۲ تا ۵ دقیقه** است.

## 🩺 عیب‌یابی

- **«هیچ کانفیگی دریافت نشد»**: دسترسی به گیت‌هاب قطع است؛ برنامه خودش از آینه‌های جایگزین (ghproxy) تلاش می‌کند. در ساعات اختلال، چند بار دکمه را بزنید.
- **«هیچ تونلِ پاسخ‌گویی پیدا نشد»**: گزارشِ قیفِ تست در همان پیام و در «نمایش گزارش اتصال» است — ببینید کدام مرحله صفر است. اگر پینگ صفر است مشکل شبکه/اختلال است؛ اگر سرعت صفر است ساعات اختلال شدید است. سرور شخصی در `my_configs.txt` همیشه بهترین راه است.
- **پروکسی روشن است ولی صفحه باز نمی‌شود**: نگهبان خودش تونل را در چند ثانیه بازسازی می‌کند؛ اگر نشد، قطع و اتصال دوباره بزنید.
- **حذف دستی پروکسی**: Settings ویندوز → Network → Proxy → Use a proxy server را خاموش کنید.
- **مطمئن شوید نسخه‌ی جدید را اجرا می‌کنید**: عنوانِ پنجره باید مثلاً `ManjarVPN v1.8.0` باشد — اگر نسخه‌ی قدیمی‌تر می‌بینید، شورتکات قدیمی را پاک کنید و exe تازه را از Releases اجرا کنید.
